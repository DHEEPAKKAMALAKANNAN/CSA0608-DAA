SentinelOps SOC Alert-Triage Module - Pseudocode 1 (OPTIMISED): sort_alerts
=============================================================================
Problem : same as the corrected version (severity desc, timestamp asc, input unchanged, stable).
Method  : stable top-down merge sort on precomputed keys key(a) = (−a.severity, a.timestamp);
          a merge is skipped when the two halves are already in order (adaptive), and only the left
          half is copied to the scratch array.
Basic op: one key comparison (tuple comparison).

Algorithm SortAlerts_Optimised(A, n)
1. P ← [ (key(a), a) for every alert a in A ]       // decorate once: n key computations
2. Aux ← array of n empty cells
3. if n > 1 then MergeSort(P, Aux, 0, n)
4. return [ a for every (k, a) in P ]               // new list; A is untouched

Algorithm MergeSort(P, Aux, lo, hi)
// sorts P[lo..hi−1] by key, stably
1. if hi − lo < 2 then return
2. mid ← ⌊(lo + hi) / 2⌋
3. MergeSort(P, Aux, lo, mid)
4. MergeSort(P, Aux, mid, hi)
5. if P[mid−1].key ≤ P[mid].key then return         // halves already in order: no merge needed
6. Aux[lo..mid−1] ← P[lo..mid−1]                    // copy the LEFT half only
7. i ← lo;  j ← mid;  k ← lo
8. while i < mid and j < hi do
9.     if P[j].key < Aux[i].key then                // strict '<': equal keys keep the earlier alert
10.        P[k] ← P[j];  j ← j + 1
11.    else
12.        P[k] ← Aux[i];  i ← i + 1
13.    k ← k + 1
14. P[k .. k + (mid − i) − 1] ← Aux[i..mid−1]       // left leftovers; right leftovers already in place

Complexity: T(n) = 2T(n/2) + Θ(n)  =>  Θ(n log n) worst and average case
            (≤ n⌈log₂ n⌉ − 2^⌈log₂ n⌉ + 1 merge comparisons + at most n − 1 order checks);
            best case (queue already in triage order) n − 1 comparisons, no moves.
Space     : Θ(n) for P and Aux.   Stable: yes.
